Data sources — how this partition view is assembled

The log (centre). The per-partition change-record log via log.recordsSince / a __dump RPC for committed values [C]. Outcomes (local / won / lost·fence / lost·conflict / dropped / forwarded) are the records' own commit classifications. View dividers come from the epoch boundaries in the stamps.

Key index (left). Each key's stamp (its winning e·s across replicas) and agree (how many of the R replicas hold that stamp) come from the ⚠ NEW per-key version sample __inspect{versions:K}, cross-merged on node uuid [A]. agree < R is a split; when the holdout also serves reads, those reads return the stale value — that's the divergence the log explains below.

Contention vs fence. A lost write's class comes from __observe's lost event, which carries the winning epoch/seq as we/ws (the value that beat it). Compare against the lost write's own epoch wr.e: wr.e == we ⇒ same-epoch conflict (true contention, it lost LWW to a higher seq); wr.e < we ⇒ fence (a stale-view write rejected — DECISIONS X) [B]. The record peek prints the lost write's own stamp as wr.e·wr.s and the winner as we·ws — the same vocabulary, never overloaded.

Replica health / lag (right). Per-replica lag from the snapshot marks/heads vs the most-caught-up floor — live origins only [A]. Which node is stuck (divergence) from the ⚠ NEW per-key version sample __inspect{versions:K} [A].

Owner by epoch. ⚠ NEW instrumentation — fero retains current ring state, not historical ownership layouts, so the e2→e3→e4 ownership history is newly recorded; today only the current owner is derivable from ring.coverage.
