Data sources — how this key autopsy is assembled

The log (centre). The per-partition change-record log via log.recordsSince / a __dump RPC, filtered to key === 'user42.score' [C]. Outcomes (local / won / lost·fence / lost·conflict) are the records' own commit classifications. View dividers come from the epoch boundaries in the stamps. This is the partition log of user42, narrowed to one key.

Version sample / divergence (right). The per-node value + stamp comes from the ⚠ NEW per-key version sample __inspect{versions:5}, cross-merged on node uuid [A]. The CURRENT / LAGS badge is each node's stamp compared to the LWW-resolved winner; agreement n/N is how many of the R replicas hold the winning stamp. n < R is a split — and because the holdout (:49807) also serves reads, those reads return its stale value. That's the divergence the log explains.

Conflict vs fence. A lost write's class comes from __observe's lost event, which carries the winning epoch/seq as we/ws. Compare against the lost write's own epoch wr.e: wr.e == we ⇒ same-epoch conflict (true contention — it lost LWW to a higher seq); wr.e < we ⇒ fence (a stale-view write rejected — DECISIONS X) [B]. The record peek prints the lost write's own stamp as wr.e·wr.s and the winner as we·ws — same vocabulary, never overloaded.

Resolved value & lag. The current value is the highest e·s across live replicas (LWW). :49807's lag (+420, not draining) is from the snapshot marks/heads vs the caught-up floor — live origins only [A].
