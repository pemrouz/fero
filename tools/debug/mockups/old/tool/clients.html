Data sources — how this client view is assembled

All per-client telemetry is ⚠ NEW. fero keeps no per-client registry today; this whole page is proposed instrumentation, assembled from the transport's live connections plus the per-subscriber push cursor.

Roster & connection. Client list, role (reader/writer), connected-server and last-seen heartbeat come from the transport's live connections per member, plus the fenced-write ack path (DECISIONS X) [D].

Subscription lag (slow-consumer). Per-subscriber cursor from the __observe push stream — lag is the subscribed key's log head minus the client's delivered seq ⚠ NEW; delivery-vs-write rate is derived the same way [B]. Log head positions are also available from the log accessor/__dump but are not the primary feed here [C].

Re-subscribe churn. Bridge-derived: joins the e3→e4 VIEW_COMMIT to each client's subscription re-target events ⚠ NEW — re-target events are not recorded today [E]. Stale view. Client view epoch vs cluster e4 from the InspectSnapshot poll (~1s) [A].
