Data sources — how this replay view is assembled

⚠ NEW This entire page is new instrumentation. fero keeps only the current ring (ring.coverage derives the live owner per partition) — it does not retain historical ownership layouts. Re-projecting the cluster at a past view (e1 / e2 / e3) requires a retained, queryable view history: each committed view's epoch, member set, and the ring it produced, recorded at commit time. Today only e4 (the current view) is derivable from live state; e1→e3 are reconstructed from the recorded transitions.

Ownership map (centre). The owner-per-partition at view T comes from re-running the consistent-hash ring for that view's member set against the 16 partition keys [E, with the NEW history store]. Gains/losses are the diff against the prior epoch's projection — the same cover diff the live tooling computes between two snapshots, applied between two retained views instead.

View-change summary (right). What moved, membership delta, and the reason come from the recorded VIEW_COMMIT events (observe kind 'view' [B]) plus the cover diff between the two views. The e3→e4 moves shown — user42 :49803→:49801 and billing :49809→:49807 — are the recorded transition.
