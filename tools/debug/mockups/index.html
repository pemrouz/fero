fero · debugging page — four design directions

Mockups only — static fake data, no backend. Each direction answers a different forensic question the monitoring dashboard deliberately doesn't. Click a card to open it full-page.

A

Key Autopsy

Why does this key hold this value? Every write attempt, who won/lost and why (epoch-fence vs seq-contention), and whether any node diverges.

B

Write Traces

Follow one write end-to-end — client, forward, owner commit, replica fan-out, acks — and see exactly where it stalled, was fenced, or died.

C

Cluster Replay

Rewind the cluster to the moment something diverged and step through what each node believed (views, gates, lag) as the incident unfolded.

D

Node Doctor

"What is wrong with THIS node" in one glance — an opinionated pass/warn/fail diagnosis with the evidence inline, not raw state to interpret.

Each mockup carries a Data sources footnote mapping every panel to its real source (InspectSnapshot field · __observe stream · log accessor · bridge-derived) — or an explicit ⚠ NEW instrumentation flag where the data doesn't exist yet.
