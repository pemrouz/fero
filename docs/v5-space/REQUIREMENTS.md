# v5 requirements: what every candidate is judged against

This is the bar for every candidate design in the v5 study. It says **what** v5 must do, never **how**. Each row has an id, one sentence, an acceptance test (how we would know it is met), its source, and **M** (MUST) or **S** (SHOULD). Ids are stable: other files cite them. Written 2026-11-06 against DESIGN-V5.md, V5-PRIMITIVE.md, V5-UNITS.md, STATUS.md, HISTORY.md, CLAUDE.md and the two product docs below. Revised the same day after two completeness critics: new rows have new ids, and the section at the end lists what was considered and left out, with the reason.

## How to read this

**Words.**
- **Partition:** the unit of order and atomicity (by default one row). **Group:** whatever unit holds a log and one writer (a shard, a lane, a cell).
- **C, one commit:** the time from a write reaching its writer to its commit. Its floor is one fsync plus one round trip to a majority. Latency bars are written as C plus an overhead.
- **Durability rungs:** `persisted` = on disk at a majority of voters before the answer; `memory` = in memory at a majority; `none` = best effort. **The default is `persisted`.**
- **Attempt:** one write or call with an id. **Exactly once** = an attempt takes effect at most once, and its answer agrees with the log. **At least once** = a delivery may repeat; **effectively once** = a repeat changes nothing, because the effect and its cursor commit together.
- Unless a row says otherwise: order is total per partition and there is none across partitions; a write's answer comes after its commit; reads of what you wrote see it.

**Sources.** V5 = [DESIGN-V5.md](../DESIGN-V5.md) (with §); PRIM = [V5-PRIMITIVE.md](../V5-PRIMITIVE.md); UNITS = [V5-UNITS.md](../V5-UNITS.md); BT = [V5-BACKTEST.md](../V5-BACKTEST.md); ST = [STATUS.md](../../STATUS.md); HIST = [HISTORY.md](../HISTORY.md); CL = [CLAUDE.md](../../CLAUDE.md); AIMS = the user's aims in [BRIEF.md](BRIEF.md); J = "fero deploy: the journey" (https://claude.ai/code/artifact/f9bd239c-cb35-4130-82f3-47ede409ec64, 2026-10-11); T = "fero test" (https://claude.ai/artifact/E52zyrNYu3XwrcuWut6RDG, 2026-11-01); SCH = data's `contract/SCHEDULE.md`; R = reasoned here.

**Numbers.** Every number below is a **bar** (a target this list sets or a source states), never a measurement, unless it says "v4 measured" or "measured here". TS = a TypeScript build; native = a Rust or other native build.

**Judging rule** (so every reader gets the same answer). Mechanisms, rules and mutants are counted as DEV-10 says.
1. **Failed, or open.** A candidate **fails a MUST by design** only when one of three things shows it: a counterexample in a model of its own mechanism; a measured ceiling below the bar (for example E-02's pipeline ceiling, which a real kernel can only approach); or a structural argument that a second agent confirms in writing. Otherwise the MUST is **open**. VERDICT.md lists every open MUST with the experiment or build phase that closes it.
2. **Out.** A candidate that fails a MUST by design is out. If every candidate fails at least one, rank them by how many MUSTs each fails, then by the sum of gap ÷ bar over those MUSTs. VERDICT.md writes down every gap.
3. **Among the rest,** compare DEV-01 counts first: if two counts differ by 2 or more, the lower count wins. Otherwise the candidate that meets more SHOULDs wins, and DEV-02 (fewer interacting pairs) breaks any tie that is left.
4. **For the user to confirm:** rule 3 ranks goal G4 (few novel mechanisms) above the SHOULD count, because G4 is why v5 exists.

**Numbers and choices the user sets.** Until the user answers, the proposed value in brackets applies, and VERDICT.md says so.
- F_w, the floor on writers per resource (SC-03, SC-10) [64].
- N_res, resources per project (SC-13) [100,000].
- The competitor-default rows where a loss is accepted by name (PERF-01) [none].
- Region scope (SC-14) [a group's voters in one region; no multi-region writes in v5].
- Whether J changes to allow a tier shared between projects (OPS-14) [yes, and J says so].
- The fsync figure for the deploy target that every latency bar is also stated against (E-01) [a cited figure].
- The order in rule 3 [as written].

**What a 4-vCPU, one-disk box cannot show** (BRIEF): real round trips between machines; independent disks (three replicas on one disk share its fsyncs, which slows every system alike, so matched runs stay fair but absolute numbers are pessimistic); NVMe latency; thread-per-core systems (Redpanda) at their intended size; more than a few real processes. Also, this box's flushes may be acknowledged from a cache under the hypervisor: a critic's probe measured a 6.4 KB `writev` plus `fdatasync` at p50 0.16-0.21 ms on the one ext4 virtual disk (scratchpad `critic/hol/results.txt`), so this box may itself be F-10's "disk that lies". E-01 checks whether flushes are honoured, and every latency bar is also stated against a cited fsync figure for the deploy target. So matched comparisons run every system in the same shape on this box, and multi-machine numbers are cited, not measured.

**The three most likely to decide the verdict.**
1. **DEV-01 with DEV-03** (few novel mechanisms, each model-checked, counted as DEV-10 says): the reason v5 exists (V5 §10.1), and where the candidates differ most. It now leads the judging rule (rule 3).
2. **SC-08 with SC-10 and SC-13** (scale up and down without worry, only stated ceilings above their floors, many resources): what separates fixed counts, lanes, slots and log-first, and it pulls hardest against DEV-01 (X4, X18).
3. **PERF-05, PERF-06 and PERF-02 at matched guarantees** (Kafka, Redpanda, Redis): the bars a TS build is least likely to meet, which decide the language and the kernel boundary (X1 to X3).

## Considered and not added

Two critics reviewed this file on 2026-11-06. Their findings were folded in above, merged where both raised the same gap. These parts were left out or changed:
- **SC-03's second floor, F_r** (1M persisted records a second per resource "in the sim at n = 32"): not added. The sim runs on virtual time and cannot measure throughput; the rate follows from F_w × PERF-09's per-writer rate, and both are already bars.
