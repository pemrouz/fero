Start

Two files: a café and a visitor.

Starting data (a seed) makes fero a server. A bare fero('cafe') is a client: it finds the server by name, keeps its own copy, and sends its writes up.

$ npm i fero

Node — or later runs the .ts files as they are.

The visitor's copy starts empty and fills in one cat at a time. Then biscuit's new mood shows on both screens, in violet. The visitor's own screen shows it only after the café has it.

How these screens were made

A real run: —, Node —, fero —. The café started first, then the visitor, each running its file exactly as shown above:

$ —$ —

The two settings keep the run to itself: a private port for the name directory (where a client looks the café up), and no config files. nice only lowers the run's priority. Ctrl-C stopped both, and both exited cleanly.
