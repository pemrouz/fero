The argument

You change one row, and fero turns that line into one record: a type, a key and a value. The row's owner stamps the record and sends it to every copy. Each copy keeps the record with the biggest stamp, so two copies that hold the same records show the same value.

Nothing shows before it commits, and nothing merges. Watch c1's line in the last card: it keeps its old value until the owner's record comes back. If two writes race for one cell, the bigger stamp wins, and the other value is gone.

    Each line is one frame a node sent, taken apart by kernel/codec.js. The ◆ line is the owner stamping the record. Grey lines are repeats. A write is sent again when no receipt has come back in time, and c1's server passes each resend on, unless it owns the row. A record is sent again when a digest says it is missing. A digest is a node's list of the highest counter it holds from each writer, and it can be out of date by the time it lands.

    While a write's frames are on the wire, the list plays it at a quarter of the cluster's pace; every time shown is still the kernel's.
